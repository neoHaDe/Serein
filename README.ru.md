# Serein

**Десктоп-клиент для серверов и сетевого железа - всё в одном окне.**

SSH, SFTP со встроенным редактором, консоль по COM-порту, telnet и сырой TCP.
Вкладки и сплит-панели, проброс портов, мониторинг ресурсов, панель Docker
и локальный терминал - в установщике на **≈ 6,7 МБ**.

Бесплатно, открытый код, Apache 2.0. Windows x64 и Linux x64, **v1.3.0**.

## ✨ Почему Serein

Интерфейс в системном WebView, SSH / SFTP / шифрование / PTY - в одном Rust-бинарнике.
Не тащим Chromium. Не пытаемся обогнать Tabby списком галочек: цель - **рабочее место
по серверу** (терминал, файлы, Docker, логи, ресурсы, туннели), а не «ещё один SSH-клиент».

| | **Serein (Tauri)** | Типичный Electron-клиент |
| --- | :---: | :---: |
| Размер установщика | **≈ 6,7 МБ** | ≈ 85 МБ |
| Память в простое | **≈ 33 МБ** | 150–250 МБ |
| SSH-движок | чистый Rust [`russh`](https://github.com/Eugeny/russh) | libssh2 / нативный |
| Рантайм | системный WebView2 | полный Chromium |

Цифры - живой `tauri dev` (RAM) и NSIS 1.2.7 (~7,8 МБ сжатый). На слабом ноутбуке те же 33 МБ не обещаем.

## 🚀 Возможности

### Server Workspace (v1.1.0)
- У SSH-вкладки - **рельса инструментов сервера**: Terminal, Docker, Logs, Processes, Services, Tunnels
- **Processes** - таблица `ps` + метрики CPU/RAM/диск сверху; **Docker** - компактный список, свойства по ПКМ
- **SFTP** - боковая панель из TabBar; список серверов при подключении сворачивается
- **↗ Открепить** вкладку или панель workspace в отдельное окно; **← вернуть** в главное окно (SSH-сессия не рвётся)

### Терминал и UX
- **Несколько SSH-вкладок** + **сплит-панели** (дерево с перетаскиванием границ, выбор сервера на панель)
- **Локальный терминал** с умным выбором shell (PowerShell → cmd, либо свой / WSL)
- Поиск (`Ctrl+F`), зум, **17 тем на весь интерфейс**, **компактный режим**
- **Своя рамка окна** (без хрома Windows): свернуть / развернуть / закрыть
- **Broadcast-ввод** (в пределах текущей вкладки), восстановление вкладок, перетаскивание вкладок
- **Ctrl+Shift+C / Ctrl+Shift+V** - копирование и вставка в терминале (не DevTools WebView2)
- Батчинг вывода SSH; при перегрузке - буфер 4 МиБ с пометкой

### Подключения
- Сайдбар с **группами и перетаскиванием**, меню по правой кнопке, поиск, **живой статус подключения**
- Аутентификация: **пароль · ключ · keyboard-interactive 2FA · SSH-агент** (выбор ключа из связки)
- **Консоль по COM-порту** - скорость, чётность, управление потоком, DTR/RTS, посылка BREAK
- **Telnet** - согласование опций, тип терминала, размер окна, BREAK/Interrupt/AYT, выбор перевода строки
- **TCP без обработки** - байты как есть, для консольных серверов
- **ProxyJump / бастион** - цепочки (рекурсивно, через `direct-tcpip`) и **ProxyCommand** (`%h %p %r`)
- **Сжатие трафика** (`zlib@openssh.com`) и режим **совместимости со старым железом**
- **TOFU-проверка known-hosts** на каждом хопе: диалог сверки, управление списком, импорт из OpenSSH
- **Переподключение при обрыве** - вручную или авто (до 5 попыток, бэкофф)
- **Теги, избранное и метки среды (v1.2.7)** - поиск понимает `tag:web`, `env:prod` и `fav`;
  прод помечен красным ярлыком в списке, видно до того, как в него что-нибудь выполнят
- **Массовый выбор (v1.2.7)** - Ctrl и Shift, как в проводнике: подключить, пометить,
  перенести или удалить сразу несколько
- Импорт из **`~/.ssh/config`**, сессий **PuTTY**, а с 1.2.7 - из **MobaXterm, XShell и SecureCRT**.
  Пароли намеренно **не** импортируются: в этих форматах они расшифровываются по устройству,
  и копировать их во второе хранилище значит размножать проблему

- Навигация по панелям с клавиатуры, настраиваемые хоткеи, **командная палитра** (`Ctrl+Shift+P`)

### Базы данных (v1.3)
- **PostgreSQL, MySQL/MariaDB и Redis** открываются каналом внутри уже поднятой SSH-сессии.
  Проброс порта поднимать не нужно: база слушает петлю сервера, туда мы и приходим
- Таблица результата, история запросов, подтверждение на разрушающие запросы. `DELETE` без
  `WHERE` спрашивает дважды, и решётка в MySQL тоже считается комментарием
- Подключение переживает переключение вкладок и открепление панели в отдельное окно
- Клиент MySQL пришлось написать свой: ни `mysql_async`, ни `sqlx` не принимают готовый
  поток, сокет они открывают сами. Разбор пакетов и скрэмблы берёт `mysql_common`

### Рабочий стол (v1.3)
- **VNC каналом внутри SSH-сессии**, без открытого наружу порта. И правильно: свой протокол
  VNC защищает паролем до восьми символов на DES, выставлять его в сеть незачем
- Кадры идут сырыми байтами, а не через JSON: экран 1920x1080 в BGRA это восемь мегабайт,
  в JSON-массиве он раздувается на порядок
- Перед подключением экран выбора: VNC и место под RDP. RDP серый, и в нём написана
  причина, а не «скоро будет»
- **Шестерёнка ставит VNC на сервер, если его там нет:** `x11vnc` в Debian,
  `tigervnc-server` в Fedora. Пароль sudo уходит на стандартный ввод, а не в строку
  команды: строка целиком видна в списке процессов сервера всем, кто там есть

### Что за система на сервере (v1.3)
- Один короткий зонд на сессию, дальше ответ запоминается. Различаются **Linux, BusyBox,
  Windows** и «непонятно»; метка видна в шапке обзора
- На **Windows Server** процессы, службы, журнал событий, диски и сеть идут через
  PowerShell, а не через `ps` и `systemctl`, которых там нет
- На **BusyBox** список процессов больше не пустой: тамошний `ps` не понимает ни `--sort`,
  ни колонки `pcpu` и молча отвечал справкой в поток ошибок. Загрузку по процессам BusyBox
  не сообщает вовсе, и там теперь прочерк, а не ноль: ноль читался бы как «простаивает»
- Плитку упавших служб не рисуют там, где systemd нет вовсе, вместо бодрого «всё в порядке»

### Файлы (SFTP)
- Просмотр с **кликабельными хлебными крошками**, **инлайн-переименование**, drag & drop внутрь окна
- **Параллельные передачи** (пул 4, до 8 в настройках), **менеджер передач**: скорость, ETA, пауза, повтор
- **Колонки как в Explorer** (имя, тип, права, размер, дата), сортировка, ресайз, Ctrl/Shift-выделение
- **Drag-and-drop с Проводником** - с сервера на рабочий стол / в Загрузки; с ПК - upload в открытую папку
- chmod, скрытые файлы, symlink follow, превью картинок; действия в меню по ПКМ
- Двухпанельный режим (локально ↔ сервер); **SFTP можно открепить** в отдельное окно
- **Ctrl+колёсико** (и Ctrl+/−/0) меняет масштаб текста в SFTP и логах
- **Встроенный редактор** (CodeMirror 6) - атомарное сохранение прямо на сервер
- **Внешний редактор** - открывает файл в редакторе ОС и сам заливает при сохранении
- **Запасной путь через SCP (v1.2.7)** - серверы без `Subsystem sftp` (старые железки,
  урезанные образы) определяются сами, и файлы идут через `scp` и `ls`

### Туннели и эксплуатация
- Проброс портов: **локальный `-L`**, **обратный `-R`**, **динамический SOCKS5 `-D`** (открытие туннеля можно прервать)
- **Мониторинг ресурсов** - CPU / RAM / диск / load (опрос `/proc` + `df`)
- **Docker-workspace (v1.2.0)** - контейнеры с живыми `docker stats`, портами и health; файлы внутри контейнера; старт/стоп/рестарт/удаление, shell
- **Docker Compose (v1.2.0)** - проекты и сервисы, up/down/start/stop/restart, логи и shell по сервису, чтение compose YAML
- **Логи Docker** - цвет уровней, follow (`-f`) со стопом, широкая панель; **открепить** на второй монитор
- **Логи хоста (v1.2.0)** - `journalctl` с подсветкой, фильтром и выгрузкой отчёта об ошибках в `.txt`
- **Логирование сессии (v1.2.0)** - запись вывода терминала в `%APPDATA%\serein\logs`, без ANSI
- **Обзор сервера (v1.2.7)** - CPU, RAM, диск, load, сеть, аптайм, ОС и ядро, число процессов,
  упавшие сервисы и здоровье Docker на одном экране
- **Железо в обзоре (v1.3)** - процессор, видеокарта с драйвером, объём и скорость памяти,
  все диски с заполненностью, у основного гигабайты, а не проценты. Видеокарта определяется
  по коду класса устройства в `/sys`, без `lspci`, которого на серверах обычно нет. Средняя
  загрузка расшифрована словами: «прямо сейчас занято столько-то из скольких ядер»
- **Одна команда сразу на нескольких серверах** (`Ctrl+Shift+M`) - результат по каждому хосту
  с кодом возврата, stdout и stderr; хосты с неизвестным ключом пропускаются с причиной,
  а не доверяются молча
- **Утилиты (v1.3)** переехали из окна поверх всего в отдельную вкладку с рельсой:
  проверка порта, диапазон портов, трассировка, HTTP-запрос, DNS, TLS-сертификат, запрос
  к каталогу LDAP, сравнение файлов. Без сервера работают калькулятор подсетей, хеши и
  разбор JWT
- **Проверки гоняются с сервера, а не только со своей машины.** «Сайт не открывается у
  меня» и «сайт не открывается с сервера» это разные неисправности с разными ответами.
  Маршрут с сервера строит `tracepath`: `traceroute` без прав root отвечает отказом
- Файл для сравнения выбирается по SFTP, а не набирается путём наизусть

### Окна
- Откреплённые вкладки, SFTP, логи и панели workspace - **отдельные окна ОС**, без рамки Windows
- **Магнит**: окна стыкуются вплотную и по направляющим (края / центр)
- Группу тащит главное окно; доп. окно отцепляется, если потянуть за него
- Aux сворачиваются **независимо** от main; свёрнутые aux вернуть - клик по Serein на панели задач или кнопка в статус-баре
- Клик по любому окну поднимает **все** окна Serein; по умолчанию **одна кнопка** на панели задач
  (в настройках можно вернуть отдельные кнопки)
- Запоминание расположения откреплённых окон после перезапуска

### Безопасность и хранение
- Секреты шифруются через **DPAPI** (Windows) или **keyring** (Linux) + опциональный
  **мастер-пароль** (scrypt → AES-256-GCM); в UI пароли и ключи не отдаются
- **Мастер-пароль от 12 символов** - без требований к составу, по NIST SP 800-63B, а не по
  привычке «обязательный спецсимвол», которая рождает `P@ssw0rd1`
- **Закрытый контур** - галочка выключает и проверку обновлений, и любые исходящие запросы.
  Исходящий запрос во всём коде ровно один, и он назван в [SECURITY.md](SECURITY.md)
- **Никаких повторов неверного пароля** - пять попыток подряд это ровно то, чем ловится
  fail2ban и блокируется учётка в Active Directory
- **Схема профиля версионируется**: перед миграцией делается копия, а профиль от более новой
  версии не переписывается молча, а отвергается
- Зашифрованный **бэкап `.tbk`** серверов, настроек и сниппетов
- **Генерация SSH-ключей** (ed25519 / RSA) + `ssh-copy-id`
- С каждым релизом публикуются суммы SHA-256 и **SBOM (CycloneDX)**; `cargo audit` и
  `npm audit` гоняются в CI на каждый пуш

## Быстрый старт

1. Поставь установщик или скачай portable `Serein_1.3.0_x64-portable.exe` из [Releases](../../releases/latest).
2. Импортируй `~/.ssh/config` или добавь сервер вручную.
3. Подключись. Локальный терминал работает и без SSH.

Цель: установка → первое соединение меньше чем за две минуты.

## 📦 Установка

С [Releases](../../releases/latest):

- **`Serein_1.3.0_x64-setup.exe`** - установщик Windows (меню Пуск, удаление).
- **`Serein_1.3.0_x64-portable.exe`** - один файл Windows, без установки. Положи и запусти. Настройки всё равно в `%APPDATA%\serein`.
- **`Serein_1.3.0_amd64.deb`** - пакет Debian/Ubuntu/**Astra** (`/usr/bin/serein`).
- **`Serein-1.3.0-1.x86_64.rpm`** - пакет **Fedora** и родственных (РедОС, Альт) (v1.3).
- **`Serein_1.3.0_amd64.AppImage`** - портативный Linux-бинарь, один файл на оба семейства.

К каждому выпуску публикуются суммы SHA-256 и **SBOM (CycloneDX)** по зависимостям Rust и npm.
Сверяй суммы: сборка под Windows **не подписана**, SmartScreen ругнётся
(*Подробнее → Выполнить в любом случае*).

Что нового - [release notes](docs/RELEASE_NOTES_v1.2.7.md) и описание выпуска на GitHub.
Политика безопасности и модель угроз - [SECURITY.md](SECURITY.md).

Автообновление работает (`nehade.xyz/updates/terminal/`), подписано minisign; ключ подписи
в CI не попадает. Его можно выключить целиком - см. закрытый контур ниже.

## 🏗 Архитектура

```
┌─────────────────────────── WebView (React) ───────────────────────────┐
│  App · TabBar · Sidebar · SftpPanel · Monitor · Docker · CodeEditor    │
│  └── src/api  ──  мост window.api  (invoke / listen)                   │
└───────────────────────────────┬───────────────────────────────────────┘
                     команды и события Tauri
┌───────────────────────────────┴───────────────────────────────────────┐
│  Rust-бэкенд (src-tauri/src)                                           │
│  ssh · ssh_agent · ssh_algos · proxycmd · serial · telnet ·            │
│  sftp · scp · remote_fs · tunnels · monitor · workspace · docker ·     │
│  pty · term_out · store · schema · vault · crypto · dpapi ·            │
│  os_secrets · keygen · importers · knownhosts · remoteedit ·           │
│  ownership · multihost · tools · error · sync                          │
└────────────────────────────────────────────────────────────────────────┘
```

- React говорит с Rust через тонкий мост `window.api` (invoke / listen).
- Одно SSH-соединение мультиплексирует **shell + SFTP + exec + туннели**; handle берётся
  коротким async-локом, каналы не ждут друг друга.
- Секреты расшифровываются **только в Rust**, в момент подключения. На Linux они лежат в
  keyring, а в файле остаётся ссылка `kr:{uuid}`: base64 - не шифрование, поэтому вместо
  настоящего хранилища не пишется ничего.
- **Владение сессией - один факт на стороне Rust** (`ownership.rs`), а не пометки в каждом
  окне. `Set` в модуле фронтенда - это состояние *одного webview*, второму окну оно не видно;
  ровно на этом расхождении до 1.2.6 умирали сессии в откреплённых вкладках.
- Файловый менеджер выбирает бэкенд один раз за сессию: SFTP там, где подсистема есть,
  и `scp` + `ls` там, где её нет (`remote_fs.rs`).

## 👩‍💻 Сборка из исходников

Нужны [Rust](https://rustup.rs) (stable) и [Node.js](https://nodejs.org) 18+.
В неинтерактивном PowerShell `cargo` часто не в PATH - добавь `$env:USERPROFILE\.cargo\bin`.

Dev-сервер слушает **`127.0.0.1:1420`**, не `localhost` (IPv4/IPv6 иначе вечно «Waiting for frontend»).

```bash
npm install
npm run tauri dev
npm run tauri build
```

Установщик: `src-tauri/target/release/bundle/nsis/`.

```bash
npm run smoke
```

(`tsc --noEmit` + `cargo check`. Сценарий целиком - `docs/PHASE0.md`.)

### Тесты

```bash
npm test                                          # фронтенд, ~100 тестов
cargo test --manifest-path src-tauri/Cargo.toml --lib
```

Интеграционные идут против **настоящих SSH-серверов в Docker** - Debian, Alpine/BusyBox и
один с намеренно вырезанной подсистемой SFTP:

```bash
./scripts/ssh-stand/up.sh
cargo test --manifest-path src-tauri/Cargo.toml -- --ignored --test-threads=1
./scripts/ssh-stand/down.sh
```

`--test-threads=1` здесь обязателен: все тесты делят один `known_hosts.json`, а приложение
переписывает его целиком. Стенд гоняется и в CI, и он уже окупился - нашёл гонку в
`known_hosts`, сломанное удаление непустой папки и четыре бага, из-за которых запасной путь
через SCP не переключался, а висел намертво.

## Данные и диагностика

Профили, секреты, known_hosts, vault - в `%APPDATA%\serein\` на Windows и
`~/.config/serein/` на Linux (`servers.json`, `secrets.json`, `vault.json`,
`known_hosts.json`, …). **Настройки показывают текущий путь** - это первое, что стоит
посмотреть, если список серверов вдруг пуст: запуск с другим `HOME` открывает другой профиль.

Секреты в UI-слой не едут. На Windows содержимое шифруется DPAPI и лежит в файле, на Linux -
хранится в **связке ключей**, а в файле только ссылка `kr:{uuid}`. Поэтому секреты с Windows
на Linux не переезжают, а там, где Secret Service не запущен, нужен мастер-пароль.

Запись вывода терминала включается по сессии и ложится в подкаталог `logs` без ANSI; общего
лог-файла приложения пока нет - для него смотри вывод `npm run tauri dev`.

## Известные ограничения

- Сборка под Windows **без цифровой подписи** - SmartScreen будет спорить. Сверяй SHA-256.
- Нет сборки под **macOS**: там без мака не проверить даже запуск, ждём железо.
- Нет **X11 forwarding**.
- Внешнего пентеста и независимого ревью крипто-слоя пока не было.
- В `rsa` висит RUSTSEC-2023-0071, исправления не существует; крейт нужен ради обычных `id_rsa`.
- Telnet не проверялся на настоящем сетевом железе - только на эмуляторе.
- Не планируется: облачный sync, мобилка, плагины, «просто чат с LLM».

Дорожная карта. 1.2.7 был про безопасность, 1.3 закрыл три позиции паритета сразу:
**VNC**, **базы данных** поверх своих же каналов и **Windows Server**. Осталось: RDP,
остальные четыре базы (SQLite, MongoDB, SQL Server), macOS и реестр отечественного ПО.
RDP отложен не «на потом», а по конкретной причине: его библиотека тянет версию
криптографии, несовместимую с нашим SSH-ядром. Подробнее -
[release notes 1.3.0](docs/RELEASE_NOTES_v1.3.0.md).
